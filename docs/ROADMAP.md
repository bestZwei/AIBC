# 路线图（ROADMAP）· AIBC

版本：v3.0 ｜ 原则：**每一阶段都要先验证上一阶段的核心假设，再谈扩张。** 旧项目失败于一次性铺开，本路线图用「留存」作为进入下一阶段的闸门。

---

## Stage 1 · 可播 MVP（✅ 已完成）

**假设要验证**：被动、连续、可插话的电台流，能带来比对话式 AI 音频更高的单次收听时长。

已交付：

- 领域核心（5 频道 + 加权调度 + 上下文记忆），纯函数 + 单测
- 服务端平台代理 + AI/TTS 适配层（密钥仅服务端、限流、缓存、错误脱敏）
- 前端连续播放（Web Audio 队列 + 预取）、实时文本、频谱可视化、ON AIR、音量、深浅主题、插话
- 工程化：TS strict、ESLint+Prettier、Husky+lint-staged、Vitest（35 例）、GitHub Actions CI
- 文档四件套（README / PRD / ARCHITECTURE / ROADMAP）

**闸门指标**：单次连续收听时长、缓冲空窗率、插话率稳定后，进入 Stage 2。

## Stage 2 · 个人化与留存（下一步）

让「我的电台」真正属于个人：

- **频道创建 UI**：自然语言描述 → 生成频道（人设 + 节目编排 + 提示词），把旧项目的核心卖点做成活的。
- **导入 / 导出**：频道配置 JSON 可迁移、可分享（纯前端，先不依赖账号）。
- **个性化记忆**：基于历史话题/偏好调整调度权重与语气（延续 `ContextMemory`）。
- **播放增强**：定时睡眠、淡入淡出/交叉淡变、失败退避重试、后台续播（PWA）。
- 共享基础设施：限流/缓存从内存迁移到 Redis（为多实例做准备）。

**闸门指标**：用户自建频道数、自建频道留存 vs 预设频道留存、次日/7 日留存。

## Stage 3 · 账号、云与内容库

- 账号体系（邮箱/OAuth）与云同步：频道、记忆、收听历史跨设备。
- 数据库落地（替换内存态）：用户、频道、生成内容与缓存。
- 内容回看：历史节目段文本/音频留存，可收藏、可重播。

## Stage 4 · 从个人到「广播网络」

- **频道市场**：发现、订阅他人频道（依赖 Stage 2–3 的 UGC 与账号）。
- **多人同步收听**：把电台大脑（scheduler）演进到**服务端 + 会话态**，支持房主与听众同步、排队插话。
- **社交轻量化**：评论区、点播、共创频道。
- 声音克隆（合规评估后）：用「我的声音」当主播。

## Stage 5 · 平台化（远期，视前四阶段数据而定）

元宇宙/沉浸式等宏大愿景**不预设**；仅当电台形态被充分验证、留存与规模成立后，才评估是否值得投入。保持范围纪律。

## 跨阶段技术债 / 待办

- [ ] e2e 测试（Playwright）覆盖「点播放→听到声音→插话→续播」黄金路径
- [ ] provider 失败的可观测性：结构化日志 + 指标（延迟、失败率、缓存命中）
- [ ] 音频格式适配层：供应商返回非 mp3/wav 时转码
- [ ] 无障碍与移动端手势：锁屏/耳机线控（MediaSession API）
- [ ] i18n 与多语种频道
- [ ] 成本控制：token 预算、按用户配额、上游熔断

> 优先级始终服务于北极星：**单次连续收听时长**。任何不提升留存、只增加复杂度的功能，往后放。
